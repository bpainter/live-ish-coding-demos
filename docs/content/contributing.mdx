`CONTRIBUTING.md` in the repo holds the setup, the rules and the DCO sign-off. This page adds what CI runs.

## Set up

```text
corepack enable
pnpm install
git config core.hooksPath .githooks
pnpm test
```

The repo pins Node in `.nvmrc`, and pnpm in `packageManager`. The hooks run `pnpm scan:private` before each commit and check the commit message.

## What CI runs

GitHub Actions. Every workflow pins its actions by full commit SHA and sets minimal permissions.

| Job             | When                              | What                                                                                                                              | Blocks                                     |
| --------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `static`        | Every pull request                | Typecheck, ESLint, Prettier, the private scan                                                                                     | Merge                                      |
| `gitleaks`      | Every pull request                | Secret scan over the whole history. A job in the `static` workflow.                                                               | Merge                                      |
| `unit`          | Every pull request                | The `node:test` units                                                                                                             | Merge                                      |
| `pack`          | Every pull request                | Packs tarballs, checks `exports`, bins and types                                                                                  | Merge                                      |
| `starter`       | Every pull request                | Scaffolds from the tarballs with pnpm and npm, builds, starts and walks                                                           | Merge                                      |
| `conformance`   | Every pull request, nightly       | Capture, `check --strict`, the Chromium walks, `axe` and cache headers on the conformance deck, and proof that each walk can fail | Merge                                      |
| `server`        | Every pull request, nightly       | Captures, checks and walks `examples/server`. A job in the `conformance` workflow.                                                | Merge                                      |
| `hosting`       | Every pull request, nightly       | Every hosting mode in Chromium and WebKit, then one host held against two origins                                                 | Merge and a release                        |
| `readme`        | Every pull request                | Runs the README quick start and the docs Quickstart from a blank folder, then checks line count and links                         | Merge                                      |
| `themes`        | Every pull request                | Contrast on all themes, then `axe`, a walk and the a11y walk per theme                                                            | Merge                                      |
| `generated`     | Every pull request                | Rebuilds theme outputs and the README theme line, compares skills to their source, and fails on a difference                      | Merge                                      |
| `skills`        | Every pull request                | Skill validation, size limits, scripted commands, and a run with agent files removed                                              | Merge                                      |
| `matrix`        | Every pull request                | Every parity row has a proving check                                                                                              | Merge                                      |
| `budgets`       | Every pull request                | Underlay and focus walks, and weight budgets                                                                                      | Warns on a pull request. Blocks a release. |
| `cross-browser` | Nightly, before a release         | WebKit and Firefox on the conformance deck and the starter                                                                        | A release                                  |
| `offline`       | Nightly, before a release         | A local-only walk with outbound traffic blocked                                                                                   | A release                                  |
| `theme-budgets` | Nightly, before a release         | Underlay walk and load budget per theme                                                                                           | A release                                  |
| `parity`        | Nightly, private runner           | `live-ish parity` on the conformance deck                                                                                         | v1.0                                       |
| `codeql`        | Weekly                            | Static security analysis                                                                                                          | Advisory                                   |
| `publish`       | A `v*` tag, once publishing is on | Runs the merge and release checks above, attaches raw results to a draft release, then stages the packages for human approval     | Nothing goes live without approval         |

The `publish` workflow is off until the owner turns it on. See the [release runbook](/release).

Pure logic tests use `node:test`, and a contributor must be able to run `pnpm test` in about a minute with no browser. A bug in the engine gets a page in `examples/conformance`.

## Add to the docs

Pages live in `docs/content/` as MDX. Each opens with an `outcome` in its frontmatter, which says what the reader will have when done. List a new page in `docs/lib/nav.ts`.

House style: sentence case headings, plain direct sentences, no em or en dashes and no exclamation marks. Tests enforce the mechanical parts, and they check every `live-ish` command against `live-ish --help`.

```text
pnpm --filter docs dev
pnpm --filter docs test
pnpm docs:build
pnpm --filter docs check:links
```

Never hand-edit a generated table. Rule pages come from `packages/engine/rules/*.md`, the theme gallery from the theme files, the budgets from `packages/verify/budgets.json` and the parity table from `parity/matrix.json`.

## Add a rule

Add the rule, its broken fixture, its tier in `catalog.ts`, and `packages/engine/rules/<id>.md`. A test fails if a rule has no page.

## Add a theme

Add `packages/engine/themes/<id>.json` and run `pnpm gen:themes`. The types, the schema, the docs tables and the README line all follow. Run `pnpm test:contrast`.
