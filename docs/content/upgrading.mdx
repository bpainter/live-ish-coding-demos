A deck takes the engine from npm. The steps depend on what changed.

| What changes                                    | How it reaches your deck                                                                           |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Engine code, runtime, default theme, validators | Update the package.                                                                                |
| Shell files                                     | `live-ish upgrade` rewrites them from the installed engine.                                        |
| Public schema                                   | `schemaVersion` in `deck.config.ts`. `live-ish upgrade` runs a codemod, and `check` names the fix. |
| Skills and `AGENTS.md`                          | `live-ish upgrade` regenerates them.                                                               |
| Frame protocol                                  | Nothing to do. The runtime and the presenter ship together.                                        |
| The starter's slides                            | Never. After scaffolding, they are yours.                                                          |

## Upgrade

```text
pnpm up @live-ish/engine
pnpm live-ish upgrade
pnpm live-ish check
```

During `0.x`, a minor can break the public API. Each break gets a changelog entry and, where possible, a codemod. All four packages share one version, so update `@live-ish/verify` with the engine if your deck has it.

## The shell

Next's App Router needs an `app/` folder in your project. A deck commits a small set of generated files, each a re-export with a "Generated by live-ish" header. `live-ish.shell.json` records what the engine last wrote.

`upgrade` rewrites an untouched file. It stops on a file you edited, and names it. `--force` overwrites it.

```text
pnpm live-ish upgrade --force
```

A file under `app/` with the header that no template names is a retired shell file, and `upgrade` removes it. A file without the header is yours, and `doctor` only mentions it.

Do not edit shell files. If you need something the shell does not offer, open an issue.

## Check your work

```text
pnpm live-ish doctor
pnpm live-ish walk
```

`doctor` checks Node, the package manager, shell hashes, ports, both local origins, `web-features` freshness and stale generated files. It warns when browser data is more than 120 days old. Update `web-features` yourself. The engine does not move it silently.

## Before a talk

Do not upgrade inside your code freeze. Upgrade, then rehearse. See the [stage-day checklist](/stage-day).
